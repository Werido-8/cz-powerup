# 0630 内部 UI 讨论会议 — 设计修改与建议梳理

> 来源：`0630 内部ui讨论会议逐字稿.txt`  
> 整理重点：设计方面提出的修改和建议

本次会议围绕**能力提升模块**和**知识库**两大块展开演示与评审。核心基调是：**先做骨干、简化复杂度，文字需求先行，原型分步迭代，上线前再与电厂用户沟通验证**。

---

## 一、整体产品策略（设计方法论）


| 原则   | 具体建议                                    |
| ---- | --------------------------------------- |
| 先简后繁 | 不要一次性把所有功能做细，先搭骨架，到各厂交流后再逐步加功能          |
| 需求先行 | 先把业务逻辑用文字稿描述清楚，再改界面原型                   |
| 分步评审 | 原型不必等全部做完再评审，做一个模块确认一个                  |
| 外部验证 | 建议拿初步思路与平圩电厂等用户沟通（如龙子峰、凤海等），专题划分可听取专业意见 |
| 原型粒度 | 初期可做静态/单页原型，不必串联知识库等后端；开发前再做交互细化        |


---

## 二、Logo 与品牌

- 当前 Logo 设计**基本认可**，可保留。
- 后续若扩展到核电等不同厂型，Logo 可再做差异化适配。
- 部署到各公司时，可考虑使用**该公司官方/团队标识**（无客户标识时可用自有品牌）。

---



## 三、能力提升模块 — 整体结构

**当前设计：**

- 普通用户：知识学习、题库、训练、个人沉淀
- 培训老师/主任：额外增加「考试管理」

**建议调整：**

- 模块划分方向认可，但各子模块需**解耦、简化**。
- 主干功能建议收敛为：**专题学习、我的学习资料、复习相关、工具入口**等，其余后期再加。

---



## 四、知识学习 / 专题学习



### 4.1 首页信息架构

**问题：**

- 顶部「最近学习 + 复习清单 + 概览」与底部「专题列表」**信息重复、偏冗余**。
- 上下两层关系不清晰：无「继续学习」时顶部显示什么？显示专题与下方有何区别？

**建议：**

- **简化顶部**，甚至可考虑去掉顶部概览，以底部专题列表为主入口。
- 专题列表应一目了然：有多少专题、哪些在学、进度如何。
- 需设计**空状态**（无学习中内容时的展示）。
- 第一版先做**简单版**：列出专题 + 基础复习计划，不做复杂跨专题聚合。



### 4.2 专题内容与维护

- 学习资料应是**经审核、评价过的精品内容**，而非知识库全量 dump。
- 需与运营/培训老师配合，按**专业**（电气、锅炉、化学、运行值班等）维护「新员工入门」等专题。
- 专题由培训老师在后台维护，可持续推出新专题。
- 建议按岗位推荐专题，用户可加入个人学习清单。



### 4.3 命名调整


| 现命名  | 建议                           |
| ---- | ---------------------------- |
| 我的学习 | 改为「**我的学习资料**」或「**我已阅读的资料**」 |
| 全部资料 | 保留，用于自由检索浏览                  |


「我的学习」语义过大，易与整个模块混淆。

### 4.4 学习路径

**问题：**

- 「基础概念 / 规程依据 / 典型操作案例」等分类**可能重复**，且难以给每个人规划固定步骤。

**建议：**

- **第一版不做刚性学习路径**（从易到难的步骤编排）。
- 专题下改为：
  - **知识点罗列**（概念性介绍，可 AI 辅助生成）
  - **文档列表**（支持标签/分类/来源筛选）
  - **思维导图、关联题目**（文档级，非章节级）
- 专题已按专业划分，无需再为每人规划第一步、第二步；用户针对薄弱点查阅即可，错题自动进入错题本。



### 4.5 AI 能力融入（方向认可，分阶段做）

- 维护专题时：AI 根据标签、文档类型、来源等**推荐文档**组成专题。
- 生成专题**知识点总结**（支持语音）。
- 根据文档**生成练习题**（需人工审核筛选）。
- 可与外部培训平台对标，突出 AI 辅助优势。

---



## 五、复习计划

**问题：**

- 与专题学习、题库功能**边界模糊**。
- 艾宾浩斯曲线对全库错题（如上千道）**不现实**。
- 与「背单词」场景差异大，不能直接照搬。

**建议：**

- 复习计划与专题学习**不要强耦合**。
- 题库侧的个人错题、自组卷等放在**题库模块**内。
- 针对某文档某章节加入复习计划 → 归入「我的学习资料」维度更合理。
- 第一版复习功能从简。

---



## 六、专项练习 & 题目与文档关联



### 6.1 核心逻辑（重要共识）

- 题目**跟着文档走**，不是从全题库随机抽。
- 类似书本章节后习题：学完文档做对应题目。
- 题库与文档题目**数据关联但入口分开**；文档题目可选入公共题库。



### 6.2 进度联动

- 文档需有**已学/未学**标记。
- 某文档关联题目全部做完 → 该文档标记为已学。
- 专题总进度 = 文档进度汇总（如 10 篇学完 4 篇 → 40%）。
- 文档内做题与专题「专项练习」入口**状态同步**（做完一边，另一边也显示已答）。



### 6.3 练习交互

- 非考试模式：可**保存记录**、做到一半退出、**清除记录重做**。
- 专题内题目做完 ≈ 该专题学习结束（可保留 revisit）。
- **不需要**按章节生成题目（过于复杂）。
- 题目来源标记到**文件级**即可，不细化到章节。

---



## 七、题库管理 vs 考试管理（重要重构建议）



### 7.1 功能拆分


| 模块       | 定位            | 使用人群       |
| -------- | ------------- | ---------- |
| **题库管理** | 题目录入、审核、分类维护  | 多人共同维护     |
| **考试管理** | 组卷、下发、成绩、参考人员 | 考试管理员（少数人） |


**现状问题：** 题库 + 试卷 + 考试全挤在一个页面，右侧区域局促、滚动不便、功能过载。

**建议：**

- **考试管理独立为一级菜单**，全屏操作空间。
- 详情页与编辑页**合并**：编辑时直接看题目详情，支持排序、换题、改题。
- 组卷流程改为**向导式**：自然语言/条件输入 → AI 出题 → 编辑筛选 → 预览 → 下发（选人、时间）。



### 7.2 考试列表与详情布局

- 左侧：历次考试列表（名称、参与人数、创建/截止时间等，信息要丰富）。
- 右侧：点击某考试后展示详情（参与人、成绩、整体统计）。
- 需同时支持**单人答题记录**和**本次考试全员汇总**视图。



### 7.3 训练模块入口梳理


| 入口          | 含义             | 建议                     |
| ----------- | -------------- | ---------------------- |
| 专题知识点练习     | 专题内、文档关联题目     | 与知识学习合并                |
| 按题库分类练习     | 从题库某分类抽题       | 保留在题库侧                 |
| 模拟考试 / 我的考试 | 老师下发的正式试卷      | 统一为「**我的考试**」，去掉「模拟」歧义 |
| 自由组卷（自测）    | 自选知识点、难度、题量、题型 | 保留，与正式考试分开             |
| 智能推荐练习      | 雷达图推薄弱知识点      | **第一版移除**，后期再加         |


- 错题本保留，需标记来源（考试错题 / 练习错题）。
- 不建议从「问答」直接生成题目。

## 八、个人沉淀

- 包含：收藏、笔记、错题本、练习记录。
- 笔记在学习文件时可添加，汇总到个人目录（用户自分类）。
- **纯个人数据，不共享**。
- 收藏功能可后期再加，不必第一版必做。

---



## 九、知识库 — 交互与 UI（重点修改项）



### 9.1 目录与知识库导航（核心问题）

**问题：**

- 目录树与知识库**断层**：点目录进文档，但看不出该目录下有几个知识库。
- 切换知识库后**状态不保留**，退出重进又变回卡片视图。
- 卡片视图与列表视图**信息不一致**：列表下搜索框、文件列表消失。

**建议：**

- 知识库作为「特殊目录」**挂在目录树下**，图标区分目录 / 知识库。
- 目录展开即可看到下属知识库数量，无需每次回退上一级。
- 切换视图（卡片/列表）时**保留搜索、文件列表**等上下文。
- 默认**展示所有文件**，搜索归搜索，不互相挤占。
- 导航条区分：**公共空间 / 部门空间**，目录与知识库用不同图标。



### 9.2 参照 Windows 使用习惯

- 目录浏览、文件管理交互应对齐用户熟悉的资源管理器习惯。
- 支持文件按**创建时间等排序**。
- 考虑**多版本文件**管理（如 2024/2025 版规程），上传时提示同名/同类型文件是否替换，历史版本保留。
- 可增加**快捷键**。



### 9.3 文件解析状态

- 普通用户：**仅可见自己上传的文件（含解析中）+ 全库已解析完成的文件**。
- 他人上传未解析完成的文件：用户不可见、不可搜、不可下载（等解析完再开放）。
- 解析状态对上传者本人可见；测试环境不应大量出现「未解析/打不开」的文件。



### 9.4 管理端简化

- 管理员文件操作按钮过多（下载、移动、停止解析、分享、切片管理等），需**按权限精简**。
- 切片管理等高级功能仅管理员可见。



### 9.5 问答模块

- 问答体验也有改进空间（如文件链接复制等），与知识库一并考量。

## 十、后续工作安排（会议共识）

1. **输出文字版需求文档**：各功能点 1-2-3 列清楚，知识库改进点单独列出。
2. **原型按模块迭代**：做一个、评一个，不必一次做完全部交互。
3. **与电厂用户沟通**：拿初步方案找平圩等厂验证，专题划分听取专业意见；可了解林海电厂使用情况。
4. **知识库测试数据**：整理调度百科等可公开文档填充测试环境，便于演示验证。
5. **开发前再做 UI 细化**：初步原型确认后，开发前由设计 + 后台一起做交互与数据库的细化设计。
