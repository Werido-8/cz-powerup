## 一、会议核心结论（方法论）

| 原则 | 说明 |
|------|------|
| 先简后繁 | 先搭骨干，到各厂交流后再逐步加功能 |
| 需求先行 | 业务逻辑用文字稿描述清楚，再改界面原型 |
| 分步评审 | 做一个模块、确认一个，不必等全部做完 |
| 外部验证 | 拿初步方案与平圩电厂等用户沟通（龙子峰、凤海等） |
| 开发前细化 | 初步原型确认后，再做交互与数据库的细化设计 |

### 2.4 专题详情与学习路径（`/learn/topic/$id`）

| # | 改动点 | 优先级 | 现状问题 | 目标 |
|---|--------|--------|----------|------|
| T1 | 移除刚性学习路径 | **P0** | 「基础概念 / 规程依据 / 典型操作案例」分类可能重复，难给每人规划固定步骤 | 第一版不做从易到难的步骤编排 |
| T2 | 专题内容结构 | **P0** | 学习路径步骤维护 | 改为：**知识点罗列** + **文档列表**（标签/分类/来源筛选）+ **思维导图、关联题目**（文档级） |

| T4 | 进度联动 | **P0** | 文档已学/未学、专题总进度 | 文档有已学/未学标记；某文档关联题目全部做完 → 文档标记已学；专题进度 = 文档进度汇总 |
| T5 | 练习交互 | P1 | — | 非考试模式：可保存记录、中途退出、清除记录重做；专题题目做完 ≈ 专题学习结束 |

| T7 | AI 能力（分阶段） | P2 | 已有部分 AI 入口 | 维护专题时 AI 推荐文档、生成知识点总结（含语音）、生成练习题（人工审核） |

### 2.6 题库管理 vs 考试管理（重要重构）

| # | 改动点 | 优先级 | 现状问题 | 目标 |
|---|--------|--------|----------|------|
| E1 | 功能拆分 | **P0** | `exam-admin.tsx` 题库+试卷+考试挤在一页，右侧局促、滚动不便 | **题库管理**（录入/审核/分类）与 **考试管理**（组卷/下发/成绩）拆为两个独立模块 |
| E2 | 考试管理全屏 | **P0** | 嵌套在能力提升子菜单，操作区域小 | 独立一级菜单，全屏操作空间 |
| E3 | 详情与编辑合并 | **P0** | 详情页与编辑页分离 | 编辑时直接看题目详情，支持排序、换题、改题 |
| E4 | 组卷向导式流程 | **P1** | 当前平铺式编辑 | 自然语言/条件输入 → AI 出题 → 编辑筛选 → 预览 → 下发（选人、时间） |
| E5 | 考试列表布局 | **P0** | 列表信息单薄 | 左侧：历次考试列表（名称、参与人数、创建/截止时间等）；右侧：点击后展示详情 |
| E6 | 双视图统计 | P1 | — | 同时支持单人答题记录 + 本次考试全员汇总视图 |

**涉及文件**：
- `src/routes/exam-admin.tsx` — 拆分或重构为两个路由
- 新建 `src/routes/question-bank.tsx`（题库管理，待定名）

### 2.9 知识库（`/knowledge`）— 重点修改

| # | 改动点 | 优先级 | 现状问题 | 目标 |
|---|--------|--------|----------|------|
| B1 | 目录树与知识库贯通 | **P0** | 点目录进文档，看不出该目录下有几个知识库；知识库未挂在目录树下 | 知识库作为「特殊目录」挂在目录树下，图标区分目录/知识库 |

| B3 | 视图切换保留状态 | **P0** | 卡片/列表切换后搜索框、文件列表消失；退出重进变回卡片 | 切换视图时保留搜索、文件列表等上下文；记住用户视图偏好 |
| B4 | 默认展示所有文件 | **P0** | 列表视图下文件消失 | 默认展示所有文件，搜索归搜索 |
| B5 | 空间导航区分 | P1 | 公共空间/部门空间不够清晰 | 导航条区分公共空间/部门空间；目录与知识库用不同图标 |

| B7 | 多版本文件 | P2 | 仅替换/不替换 | 上传同名/同类型文件时提示是否替换，历史版本保留 |
| B8 | 解析状态可见性 | **P0** | 测试环境大量未解析文件；他人上传未解析文件对用户可见 | 普通用户仅见：自己上传的（含解析中）+ 全库已解析完成的；他人未解析不可见、不可搜、不可下载 |
| B9 | 管理端按钮精简 | P1 | 下载、移动、停止解析、分享、切片管理等按钮过多 | 按权限精简；切片管理等高级功能仅管理员可见 |
| B10 | 问答模块联动 | P2 | 文件链接复制等体验问题 | 与知识库一并考量改进 |

### Phase 1：导航与模块拆分（预估 2–3 天）

**目标**：先把「骨架」搭对，不动细节交互。

| 任务 | 文件 | 动作 |
|------|------|------|
| 1.1 考试管理升一级菜单 | `Header.tsx` | 从「能力提升」子菜单移出，与「题库管理」并列（或「能力提升」下只保留学习相关） |
| 1.2 拆分 exam-admin | `exam-admin.tsx` | 拆为 `question-bank`（题库管理）+ `exam-admin`（考试管理），或 Tab 级拆分但全屏 |
| 1.3 训练入口精简 | `training.index.tsx` | 移除「智能推荐」入口；「模拟考试」→「我的考试」 |
| 1.4 路由注册 | `routeTree` / 路由文件 | 新增题库管理路由，更新导航高亮逻辑 |

**验收**：菜单结构符合会议共识；考试管理有独立全屏空间。

### Phase 2：知识学习首页简化（预估 2–3 天）

**目标**：去掉冗余概览，专题列表成为主入口。

| 任务 | 文件 | 动作 |
|------|------|------|
| 2.1 简化顶部 | `learn.index.tsx` | 移除或大幅简化 `HeroOverviewCard`、`TodayReviewHeroCard`、顶部复习聚合 |
| 2.2 Tab 重命名 | `learn.index.tsx` | 「我的学习」→「我的学习资料」 |
| 2.3 专题列表强化 | `learn.index.tsx` | 展示专题数量、在学状态、进度；补充空状态 |
| 2.4 复习计划下沉 | `spaced-review.tsx` | 从首页移除跨专题复习聚合，保留文档级简单提醒（可选） |
| 2.5 Mock 数据 | `learning-hub.ts` | 对齐新信息架构 |

**验收**：首页以专题列表为主，无上下重复信息；空状态有设计。

### Phase 3：专题详情与学习路径（预估 3–4 天）

**目标**：文档-centric 学习，题目跟文档走，进度联动。

| 任务 | 文件 | 动作 |
|------|------|------|
| 3.1 移除学习路径步骤 | `learn.topic.$id.tsx` | 去掉「基础概念/规程依据/典型操作案例」刚性路径 |
| 3.2 专题内容三区 | `learn.topic.$id.tsx` | 知识点列表 + 文档列表（筛选）+ 关联题目/思维导图 |
| 3.3 文档已学标记 | `learn.doc.$id.tsx` | 已学/未学；关联题目做完 → 自动已学 |
| 3.4 做题状态同步 | `learn.doc.$id.tsx`、练习页 | 文档内做题与专题专项练习状态一致 |
| 3.5 练习交互 | 练习相关路由 | 保存记录、清除重做（非考试模式） |
| 3.6 题目来源 | Mock / 类型定义 | 来源标记到文件级，不细化章节 |

**验收**：学完文档题目即标记已学；专题进度按文档汇总；两个做题入口状态一致。

### Phase 4：考试管理重构（预估 4–5 天）

**目标**：独立全屏、详情编辑合一、列表信息丰富。

| 任务 | 文件 | 动作 |
|------|------|------|
| 4.1 左右分栏布局 | `exam-admin.tsx` | 左：考试列表（名称、参与人数、时间）；右：详情/编辑 |
| 4.2 详情编辑合并 | `exam-paper-editor.tsx` 等 | 编辑态直接展示题目详情，支持排序/换题/改题 |
| 4.3 组卷向导（P1） | 新建 wizard 组件 | 分步：输入条件 → AI 出题 → 编辑 → 预览 → 下发 |
| 4.4 成绩双视图 | `exam-admin.tsx` | 单人记录 + 全员汇总 |
| 4.5 题库管理页 | 新建或拆分 | 题目录入、审核、分类维护 |

**验收**：考试管理独立全屏；列表信息丰富；编辑体验不局促。

### Phase 5：知识库导航重构（预估 4–5 天）— 重点

**目标**：目录树贯通、视图状态保留、解析可见性规则。

| 任务 | 文件 | 动作 |
|------|------|------|
| 5.1 数据结构 | `knowledge-space.ts` | 知识库作为目录树子节点；图标类型 `folder` / `knowledge-base` |
| 5.2 目录树 UI | `knowledge.tsx` | 展开目录可见下属知识库及数量 |

## 六、建议实施顺序

```
Phase 0（文档）→ Phase 1（导航拆分）→ Phase 5（知识库，独立可并行）
                → Phase 2（学习首页）→ Phase 3（专题/文档）
                → Phase 4（考试管理）
                → Phase 6（验证）
```

**理由**：
1. **Phase 1** 先定菜单骨架，后续改动有锚点。
2. **Phase 5 知识库** 与学习能力提升相对独立，可与 Phase 2/3 并行。
3. **Phase 2→3** 知识学习是会议讨论最多的部分，需 sequential 改。
4. **Phase 4** 考试管理改动面大，依赖 Phase 1 拆分结果。
