## 二、知识库模块

### 2.1 导航与信息架构

**已介绍方案：**

- 导航简化为三块：**我的、部门空间、公共空间**
- 页面层级：空间 → 知识库列表 → 库内详情（目录树 + 文件列表）→ 文件预览（左目录、中预览、右思维导图等）
- 库内详情：左侧文件目录树，中间文件列表；顶部有检索；库名可下拉快速切换同部门下其他库
- 文件版本：弹窗展示历史版本；目录树旁有历史 icon 标识多版本文件

### 2.2 权限体系（重点，需重做表格）

**角色定义：**

- 知识库管理员、部门管理员、普通员工
- 层级：部门 → 知识库 → 库内文件

**提出的问题：**


| #    | 问题                                                  | 状态/结论                                                            |
| ---- | --------------------------------------------------- | ---------------------------------------------------------------- |
| K-07 | 分配权限时是否要区分**下载 vs 查看**等细粒度？                         | 待梳理；当前描述不清                                                       |
| K-08 | 不同员工对**哪个库**有权限？权限在 UI **哪里体现**？表格每列含义是什么？          | **权限表格需重新整理**                                                    |
| K-09 | 普通员工对部门库/公共库的**上传、编辑、删除**权限描述是否准确？                  | 需区分「空间管理」vs「库内文件操作」                                              |
| K-10 | 权限按**部门**还是按**单个知识库**设置？员工可有多个身份（个人库、所属部门、申请访问的其他库） | 应从**知识库本身**设权限，非仅从部门角度                                           |
| K-11 | 普通员工在**有权限的知识库内**做文件相关操作；可申请某库的下载/上传/查看权限           | 已认同，文案需改准确                                                       |
| K-12 | 员工个人库内容想分享给他人：领导要求放到部门/公共空间时，是**移动还是复制**？           | **此前未考虑**；员工可移到有权限的库                                             |
| K-13 | 上传到部门库/公共库是否都要审批？                                   | **不一定**：有上传权限则无需审批；**公共空间**上传可能需公共空间管理员审批；部门库用权限控制               |
| K-14 | 部门新建知识库时应可设**默认权限**（如部门成员默认查看/下载等）；其他人申请或主动授权       | 待设计                                                              |
| K-15 | 公共空间下可有多个知识库；**非公共空间管理员不能随意上传**                     | 已确认                                                              |
| K-16 | **新建部门**时的「全员可见」选项是否必要？部门节点是否默认全员可见？                | 评审意见：部门节点层面**无需过于复杂**；能否看某库内文件是**知识库权限**问题；部门结构全场应一致（见「存疑句」S-01） |
| K-17 | 文件操作权限：**查看、下载、上传、编辑、删除、移动**共五个；是否可简化分组？            | 建议：查看+下载合并；修改+删除合并；上传单独；部分权限**固定不可配**（如部门管理员可删）                  |
| K-18 | 删除是逻辑删还是物理删？与 **RAG 召回**关系？                         | 需结合技术明确；若能召回则倾向物理删                                               |
| K-19 | **修改基本信息和元数据**也是权限问题                                | 需纳入权限梳理                                                          |
| K-20 | 三种系统角色 × 知识库权限存在**大量交叉**，本期先定知识库侧权限                 | 需综合个人/部门管理员/知识库管理员需求                                             |
