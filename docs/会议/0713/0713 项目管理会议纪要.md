| # | 问题/议题 | 结论 |

### 2.2 人天 / 成本 / 进度——会议中提出的概念问题

> 说明：以下多为 3 号追问、2 号当场澄清；落地时按此理解操作即可。

| # | 问题 | 结论摘要 |
| --- | --- | --- |
| C-01 | 能否从 PingCode 直接同步「计划」维度？ | **维度不同**：里程碑计划是规划视角；PingCode 是任务执行视角，计划与实际常不一致 |
| C-02 | 「人天」是否等于「几个人 × 几天」？ | 人天是**工作量计量单位**（1 人做 3 天 = 3 人天；3 人做 3 天 = 9 人天），含开发/自测/修 bug 等除非测试单列 |
| C-03 | 任务必须改成「完成」才计入消耗？ | **否**。只要安排了工时，生成周报时就会计入消耗 |
| C-04 | 小偏差要不要每周改系统？ | **细微偏差**（如差 0.5～1 人天）可不改；**大偏差**（排了 4～5 人天却完全没干/出差等）必须按实际调任务/人员后再生成周报 |
| C-05 | 进度百分比怎么填？和 PingCode 消耗有无关系？ | **无关**。消耗来自工时安排；完成%是项目经理对成果的**主观判断**（要看实际交付物，必要时问成员） |
| C-06 | 本周消耗多人天但只完成约 10% 怎么办？ | 按 10% 更新进度；周报中会出现「消耗人天 ≫ 完成人天」，需在**问题与风险**里写原因并复盘 |
| C-07 | 出差怎么记任务？ | PingCode 可挂在「需求调研」类需求/任务下；里程碑里可有需求调研项，**不必拆到每个现场** |
| C-08 | 财务「分摊」是什么？ | 按个人本月应工时与实际填工时比例分摊到项目；偏差大再人工维护；偏差不大时可不必过度关注 |
| C-09 | 成本超预算常见原因？ | ① 实际消耗持续大于完成；② **功能范围膨胀**导致预估人天总和超过成本预算 |
| C-10 | 需求一直加，何时该控？ | 立项后以合同成本为约束；大增需求优先引导客户报新年项目；未批项目有风险，最多选择性预做一部分，**拿不准时找 2 号一起定** |

## 四、管理原则（会议强调、非介绍细节）

1. **双维度盯盘**：成本消耗（工时/周报）与工作完成（人天进度%）理想应大致匹配；长期失衡需评估里程碑风险。  
2. **计划可调**：改时间 / 加班赶工 / 减范围 / 挪工作，都是常规手段；与干系人（含客户）对齐理由。  
3. **项目经理念念**：进度判断、风险归因、需求边界由项目经理唯一扛责，不能只会「再去问一遍开发」。  
4. **合同约束成本**：有多少钱干多少活；超预算要上报商量加人天或砍范围，而非默默超支。
