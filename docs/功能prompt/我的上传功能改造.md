可以按**文件生命周期状态动态展示操作**。这类“我的上传”页面不适合每行固定显示同一批操作，应该让当前最重要的动作随状态变化。

另外，待审核时建议使用 **“撤回申请”**，不要叫“取消审核”。“取消审核”更像管理员中止审批；上传人主动撤回自己提交的文件，用“撤回申请”更准确。

## 推荐的状态—操作矩阵

| 当前状态     | 推荐主操作   | “更多”菜单                  | 操作后的状态  |
| -------- | ------- | ----------------------- | ------- |
| 草稿/已撤回   | 提交审核    | 编辑信息、预览、删除              | 待审核     |
| 待审核      | 撤回申请    | 预览、查看详情、下载原文件           | 已撤回     |
| 被驳回      | 修改并重新提交 | 查看驳回原因、预览、下载、删除         | 待审核     |
| 未解析      | 开始解析    | 查看详情、下载原文件、删除           | 解析中     |
| 解析中      | 查看进度    | 终止解析、查看详情、下载原文件         | 未解析     |
| 解析失败     | 重新解析    | 查看失败原因、替换文件、查看详情、删除     | 解析中     |
| 解析成功/待发布 | 查看解析结果  | 查看分块、下载、查看详情            | 等待发布    |

## 各状态建议重点设计

### 1. 待审核

推荐菜单：

```text
撤回申请
────────
预览文件
查看提交详情
下载原文件
```

撤回后不要直接删除数据，应回到“已撤回”或“草稿”状态，允许用户修改后重新提交。

确认提示：

```text
撤回审核申请？

撤回后，该文件将不再进入审批流程，
你可以修改文件信息后重新提交。

取消    确认撤回
```

---

### 2. 被驳回

这一状态最重要的不是普通预览，而是让用户知道**为什么被驳回、下一步怎么办**。

推荐菜单：

```text
查看驳回原因
修改并重新提交
────────
预览文件
下载原文件
删除记录
```

建议把“修改并重新提交”作为最突出操作。

如果修改了：

* 文件本体；
* 目标知识库；
* 文件名称；
* 分类或标签；

重新提交后回到“待审核”。

---

### 3. 解析中

推荐不要只显示一个静态“解析中”状态，操作中增加：

```text
查看解析进度
终止解析
────────
查看文件详情
下载原文件
```

这里建议使用“终止解析”，比“取消解析”更准确。

终止解析需要确认：

```text
终止文件解析？

终止后，本次解析任务将停止，
文件将恢复为“未解析”状态。

取消    确认终止
```

解析过程中建议禁止：

* 替换文件；
* 修改关键元数据；
* 删除文件；
* 再次发起解析。

避免产生并发任务或状态冲突。

---

### 4. 解析失败

推荐菜单：

```text
查看失败原因
重新解析
────────
替换文件
查看文件详情
下载原文件
删除记录
```

其中：

* **重新解析**：原文件不变，重新执行解析；
* **替换文件**：文件内容发生改变，原则上应重新进入审核流程；
* **查看失败原因**：展示错误阶段、错误描述和处理建议。

例如：

```text
失败阶段：文档内容提取
失败原因：文件已加密，无法读取正文
处理建议：取消文件密码后重新上传
```

“重新解析”点击后直接进入“解析中”，通常不需要复杂弹窗，但要防止重复点击。

---

### 5. 未解析

如果解析由用户主动触发：

```text
开始解析
────────
查看文件详情
下载原文件
删除文件
```

如果系统在审批通过后自动解析，那么用户端不应该出现“开始解析”，只展示：

```text
等待系统解析
查看文件详情
```

也就是说，“开始解析”是否出现取决于实际流程，不要做一个无法真正控制任务的假按钮。

---

### 6. 解析成功但未发布

如果系统存在“解析成功后还需要管理员发布”，建议增加一个中间状态：

```text
待发布
```

用户端菜单：

```text
查看解析结果
查看文件详情
查看分块内容
下载原文件
```

普通上传人不应显示“发布”按钮，除非他拥有发布权限。

管理员端则可以显示：

```text
发布
重新解析
查看解析结果
停用文件
```

---

### 7. 已发布

推荐菜单：

```text
预览文件
下载文件
复制访问链接
版本记录
────────
上传新版本
申请下架
```

已发布文件不建议让普通上传人直接删除，否则可能影响：

* 知识问答引用；
* 历史访问链接；
* 版本记录；
* 审核追踪；
* 已生成的题目或知识内容。

更合理的是“上传新版本”或“申请下架”。

上传新版本后建议：

```text
上传新版本
→ 待审核
→ 解析中
→ 发布新版本
```

旧版本在新版本发布前继续有效。

---

### 8. 已停用或已下架

推荐菜单：

```text
查看停用原因
申请恢复
────────
查看文件详情
版本记录
上传新版本
```

用户端使用“申请恢复”，管理员端才使用“恢复启用”。

---

## 操作列的展示方式

当前列表操作列只有“···”，这种方式可以保留。建议鼠标点击后，根据当前状态动态生成菜单。

不要所有状态都显示十几个菜单项，而是控制在：

* 1 个当前主操作；
* 2～4 个辅助操作；
* 危险操作放在菜单最下面。

例如：

### 待审核

```text
↩ 撤回申请
────────
◉ 预览文件
ⓘ 查看详情
```

### 解析中

```text
◷ 查看解析进度
■ 终止解析
────────
ⓘ 查看详情
```

### 解析失败

```text
↻ 重新解析
ⓘ 查看失败原因
────────
⇧ 替换文件
🗑 删除记录
```

### 已发布

```text
◉ 预览文件
↓ 下载文件
🔗 复制访问链接
◷ 版本记录
────────
⇧ 上传新版本
↘ 申请下架
```

实际实现使用项目现有线性图标，不使用 emoji。

## 操作权限需要区分

### 普通上传人

可以：

* 撤回自己的待审核文件；
* 修改并重新提交；
* 重新解析自己有权限管理的文件；
* 上传新版本；
* 申请下架或恢复。

不建议直接允许：

* 审批通过；
* 发布；
* 停用；
* 恢复启用；
* 删除已发布文件。

### 管理员

可以额外执行：

* 通过、驳回；
* 发布；
* 停用、恢复；
* 终止解析；
* 重新解析；
* 删除或移入回收站；
* 修改目标知识库和权限。

---

## 推荐最终状态流转

```text
草稿
  ↓ 提交审核
待审核
  ├─ 撤回申请 → 已撤回 → 修改后重新提交
  ├─ 审批驳回 → 被驳回 → 修改后重新提交
  └─ 审批通过
        ↓
      未解析 / 解析中
        ├─ 终止解析 → 未解析
        ├─ 解析失败 → 重新解析
        └─ 解析成功
              ↓
            待发布
              ↓
            已发布
              ↓
            已停用 / 已下架
```

其中最推荐优先实现的动态操作是：

```text
待审核：撤回申请
被驳回：查看原因、修改并重新提交
解析中：查看进度、终止解析
解析失败：查看原因、重新解析
已发布：预览、下载、版本记录、上传新版本
```
